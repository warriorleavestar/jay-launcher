# Jay 公共网络

> **实验功能**：已通过自动测试和本机真窗口自检，还没有在两台不同网络的电脑上实测。

## 是什么

打开联机页，点「连接公共网络」，所有人先进同一个公共网络。它只用来**看房间列表、找房主、敲门**。房主批准以后，游戏、聊天、远程控制都在房主自己的网络（子网）里走，用的还是敲门后拿到的每人一把的钥匙。

| 层 | 是什么 | 谁能进 |
|---|---|---|
| 公共网络 | 一个固定名字的 EasyTier 网络（10.235.0.0/16），密钥是公开的 | 任何人 |
| 房间目录 | 跑在种子节点上的小服务（10.235.0.1:47668），只存房主签过名的房间信息 | 公共网络里的 Jay |
| 子网（房间） | 房主自己的 EasyTier 网络，钥匙在敲门后经加密通道发放 | 房主批准的人 |

公共网络的密钥谁都知道，所以 Jay 把它当作没有保密：

- 在公共网络里**只开敲门端口**（TCP 47660），其他端口都不放行。
- **不打洞**（`--disable-p2p`），所有流量经种子节点转发，别人看不到你的公网 IP。
- 主机名固定为 `jay`，不暴露电脑名。

## 房间的四种方式

房主开好房间后，在「Jay 公共网络」卡片里选：

- **隐藏**（默认）：不进列表。拿着你的邀请码的人，Jay 会先在目录里找你，再经公共网络敲门，不用等邀请码自己的大厅。
- **公开**：进列表，谁都能「申请加入」。可以勾「自动批准」。
- **密码**：列表里带锁。密码不发给任何人，Jay 用 PBKDF2-SHA256（60 万次）由密码和房间的盐派生敲门令牌。密码不对，握手就失败。房主那边失败太多会暂停敲门 60 秒。
- **直连**：列表里放房主的直连码。加入方点一下就开始打洞，生成的回复码经目录自动转给房主，不用手动互发。

## 防伪造

- 每个房间有一把 Ed25519 签名钥匙（房间关掉就扔），**房间编号 = 签名公钥的 SHA-256 前 16 字节**。
- 目录只认签名对、序号更大的版本。别人改不了你的房间，也不能拿旧版本重放。撤下请求同样要签名。
- 列表里登记了房主的联机身份公钥。加入方敲门时核对握手里的房主公钥，对不上就停止（防止有人在目录里冒用别人的房间）。

这样以后可以把房间列表同步到多个节点（志愿节点），不用改协议。

## 设备指纹

默认关着，用户在联机页“设备指纹”里打开后才生成。本机存两样东西（和联机身份一样加密保存，文件 `device-fingerprint.key`）：

- **指纹密钥**：32 字节随机数，用来生成指纹码。
- **设备签名钥匙**：Ed25519，敲门时证明“我是这台设备”。房主看到的“设备 XXXX-XXXX-XXXX-XXXX”是它的公钥指纹。

**指纹码** `JAYF1-XXXX-XXXX-XXXX-XXXX-XXXX`：版本号之后是 12 字节，前 5 字节是随机数，后 7 字节是 `HMAC-SHA256(指纹密钥, "jay-fp-v1" ‖ 随机数)` 的前 7 字节，用 Crockford Base32 写出来。

- 每点一次“生成新的指纹码”就是一个新码（随机数有 2^40 种），不同的码之间看不出是同一台电脑。
- 拿着指纹密钥的一方能认出每一个码都属于这台电脑。
- 版本号决定算法：以后换算法就加 `JAYF2`，旧码按旧算法照样认。
- 不绑硬件。“换新”生成新的密钥和签名钥匙，以前给出去的码全部作废；“关掉”删掉文件。

**按指纹码找房间**：房主发布时勾“可以用我的指纹码找到这个房间”，发布 / 续期时把指纹密钥交给目录（先到先得）。别人在“用指纹码找房间”里输入码，目录拿每个登记了密钥的房间算一遍标签，对上了就返回那个房间的签名信息。隐藏房间开了指纹查找时会带一张要房主批准的长期邀请，只有拿着码的人能从目录里拿到，不进公开列表。

**加入的设备要求**（房主在发布设置里勾）：

- “加入的人必须打开设备指纹”：敲门握手的第二条消息里房主说要设备证明，加入方用设备签名钥匙签“房主公钥 ‖ 自己的联机公钥”发回去，换个房主或换个人这份证明都用不了。没打开的人收到“房主要求设备指纹”。
- “只让这些电脑进”：房主贴上对方给的指纹码。握手时房主只发这些码的随机数（不发标签），加入方按自己的密钥算出标签发回，房主和码里的标签比，对上了才放行。
- 加入方只在房主要求时才发设备证明，房主不问就不发。

注意：

- 打开了指纹查找的房主，目录服务（种子节点的运营者）知道他的指纹密钥，能认出他的码，也能替他算出标签，所以“只让这些电脑进”对目录运营者不设防。
- 一个同时也是房主的恶意第三方理论上可以把别的房主的随机数转给你、再把你的标签转回去，冒充名单里的你，前提是他拿到了你发给那个房主的码，而且你恰好也在敲他的门。
- 这两点在“只让名单里的电脑进”的场景里可以接受，以后再收紧。

## 换别的公共网络

别人搭的公共网络用一串 `JAYNET1-...` 的连接串分享：联机 → 公共网络 → 公共网络，粘贴后“添加网络”，下拉框里切换。

- 连接串 = 网络信息（编号、名字、EasyTier 网络名和密钥、节点、版本号、可选的过期时间 / 主页 / 服务器配置文件的地址和 SHA-256）+ Ed25519 签名。内容改一个字节签名就不对。
- 前缀里的数字是格式版本；以后换算法就换数字，看到更新的版本会提示先更新 Jay。
- Jay 注册表钥匙签的显示“Jay 已审核”，直接加；别人签的显示签名钥匙的短指纹，提醒后用户确认才加，下拉框里带 ⚠。
- 同一把钥匙签的更大版本号会替换旧的；同一个编号换了钥匙的拒绝，要用户先删掉旧的（防冒用）。编号 `jay` 只认注册表签的，用来给内置网络补节点。
- 设置里只存连接串原文，每次启动都重新验签，过期或被改过的直接不用。
- 换网络会先断开旧网络（公开的房间也会撤下）。

审核流程见 [networks/README.md](../networks/README.md)：在 `networks/` 提交 JSON → PR 检查格式 → 维护者审核合并 → CI 用注册表钥匙签名，发到 `networks` Release。
注册表钥匙还没生成：生成后私钥放进 `network-registry` environment 的 secret `JAY_NETWORK_KEY`，公钥写进 `NetworkString.RegistryKeys`。

自己搭网络：`jay-server network keygen` → `network sign` → `jay-server directory --network <连接串>`。

## 网络配置文件

连接串里可以带 `config: {url, sha256}`。连这个网络之前，Jay 先取配置文件：本机缓存（按哈希命名，在 `network-configs/`）对得上就直接用，否则从 https 地址下载（最多 256 KB），SHA-256 对不上就不连。所以配置文件和连接串一样改不了，改了要发新版本的连接串。

```json
{ "v": 1, "network": "nz-friends", "notice": "欢迎……",
  "links": [{ "name": "规则", "url": "https://example.org/rules" }],
  "policy": { "modes": ["public", "password"], "requireDevice": true, "files": true, "maxFileMB": 2048, "minVersion": "0.8.0",
              "security": { "attestation": "required", "breaker": "on", "restartDelayMin": 30 } },
  "login": { "required": true, "key": "<登录公钥>", "signKey": "<发凭证的公钥>", "factors": ["totp"], "requireFactor": false },
  "ui": { "...": "界面主题，见 docs/themes.md" } }
```

- `notice` 和 `links` 显示在公共网络卡片上，链接只认 https，用系统浏览器打开。
- `policy` 只能比默认更严：`modes` 是这个网络上允许公开的房间方式（隐藏房间总是可以），`requireDevice` 让这个网络上开的房间都要求设备指纹，`files` / `maxFileMB` 关掉或限制成员之间传文件（收发两头都查），`minVersion` 是最低 Jay 版本，`security` 是最低安全要求（设备验证 off/on/required、冒充熔断 off/on、熔断后重启前至少等几秒），和本机设置合并时只取更严的，写错整份配置都不用。
- `ui` 是这个网络的界面主题，格式见 docs/themes.md（网址 + sha256 + 大小，或内联配色）。连上后只在联机页用；`scope: "global"` 时 Jay 先问用户要不要整个换掉。断开就换回自己的主题；取不到或格式不对不影响联机。设置里关掉“网络主题”就都不用。
- `login` 见下一节。

## 网络账号（账号密码 + 两步验证）

账号由网络维护者在自己的节点上管，Jay 不经手、不保存账号库。

1. 节点上开登录：`jay-server directory --accounts ...`。第一次会在数据目录生成 `login.key`（不要外传），并打印要写进网络配置的 `login` 段。
2. 加账号：`jay-server account add <账号>`（密码在终端输入，至少 8 位；脚本里可以用环境变量 `JAY_ACCOUNT_PASSWORD`）。还有 `passwd`、`remove`、`disable`、`enable`、`list`。
3. 两步验证：`jay-server account 2fa on <账号> [--issuer <网络名>]` 打印密钥和 `otpauth://` 地址，用任何验证器 App（Google / Microsoft Authenticator 等）添加；`2fa off` 关掉。`directory --require-2fa` 让没开两步验证的账号登录不了。
4. 第三方验证方式：`directory --factor <名字>:<提示>:<程序>`（可以多个，用逗号隔开）。登录时 Jay 显示“提示”让用户填，节点把 `{"user","response","network"}` 写进程序的标准输入，退出码 0 = 通过，10 秒没结束算不通过。邮件码、短信、会员系统、人工审核都可以这样接。写 C# 的也可以直接实现 `ILoginFactor` 接口挂到 `LoginAuthority.Factors`。

怎么保护的：

- Jay 用自己的联机身份把账号密码（和验证码）加密给节点的登录公钥（X25519 + AES-GCM，和私聊同一套），公共网络上别人看不到；带时间戳，5 分钟外的旧请求不认。
- 节点只存 PBKDF2-SHA256（60 万次）的盐和哈希。连续错 5 次（密码或验证码都算）锁 5 分钟；账号不存在和密码错的回答一样。密码对了要不要两步验证、验证码对不对，也加密发回，旁人看不出密码对没对。
- 登录成功后节点发一张凭证：账号名 + 登录人的联机指纹 + 网络编号 + 7 天有效期，节点用 `signKey` 签名。凭证绑定指纹，被别人看到也没法用。
- `required: true` 时，这个网络上开的房间敲门时都查凭证（房主用 `signKey` 自己验，不用联系节点），没登录的被拒，提示“这个网络要求登录账号”。房主的敲门卡片上能看到账号名。
- 凭证只放在 Jay 的内存里，关掉 Jay 或换网络就要重新登录。停用账号后已发的凭证最多 7 天后失效。

## 部署种子节点

找一台有公网 IP 的机器（Linux / Windows / macOS 都行），放行 **TCP 和 UDP 的 11010** 端口：

```bash
jay-server directory --listen 11010
# 第一次运行会自动下载 EasyTier（校验 SHA-256）。已经有 EasyTier 的可以用 --easytier <文件夹>。
# 有别的种子节点时：--seeds tcp://另一台:11010
```

然后在每个人的 Jay 里：联机 → Jay 公共网络 → 公共节点，填 `tcp://<这台机器的公网地址>:11010`，保存。

Linux 上长期运行可以用 `server/jay-public-node.service`（systemd）。

这台节点同时也会被加进房间用的中继节点，所以经公共网络找到的房主和加入方在它上面一定碰得上面。

## 自检

```bash
AMBER_SELFTEST=<报告目录> AMBER_SELFTEST_SCOPE=public-network AMBER_DATA_DIR=<测试数据目录> Jay
```

在本机开一个种子节点，走完：连接（第一次显示隐私说明）→ 开房间 → 公开发布 → 另一个成员在列表里看到并加入 → 改成密码房间（密码错进不去、对了能进）→ 设备指纹（默认关着、码每次不同、隐藏房间按码找到、要求设备指纹、名单 + 批准后进入、换新后旧码失效）→ 撤下 → 断开 → 换公共网络（审核过的直接加并连进去、没审核的先提醒、同编号换钥匙拒绝、删掉回到 Jay 网络、网络配置的公告 / 链接 / 策略 / 最低安全要求、网络主题（只在联机页、global 先问、断开换回）、网络账号登录（密码错、要两步验证码、码对了登录、退出和断开后凭证作废）、取不到配置就不连）。需要先下载好联机组件。

用真 EasyTier 跑核心流程的单元测试：设置 `JAY_ET_DIR=<放 easytier-core 和 easytier-cli 的文件夹>` 后运行 `PublicNetworkEasyTierTests`。
